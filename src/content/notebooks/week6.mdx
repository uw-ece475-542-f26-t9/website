## Weekly Progress

- Soldered Xiao battery pads, LRA pads, and DRV2605L breakout board
  connections.
- Built the full device on a breadboard and confirm that the device
  connects to the frontend and transmits IMU and EMG data while battery
  powered.
- Finalized and tested power delivery circuits to power the Myoware
  directly from the battery, important for keeping consistent readings
  despite battery voltage drop as it drains.
- Verified that the haptic motor worked in a standalone test, and then
  integrated with its power circuit.
- Deployed a preliminary test model to the ESP.

## Outcomes and Decisions

- We prioritized getting the full prototype working end to end, deciding to breadboard
  and test thoroughly rather than jump to a perfboard solder. Verified sensor acquisition,
  app display, and haptic feedback together on battery power before refining individual
  features.
- Keep model research and firmware integration moving in parallel. Use the available
  sensor data to explore features for fatigue estimation while continuing hardware tests.
- Use periodic vibration to test haptic feedback during integration. In the current
  setup, sensor readings reach the app, and the motor works on its own. Integration will
  follow from AI model results.

## Next steps

- Finalize which time-frequency methods we will use in the data.
- Finalize data collection proceedure.
- Complete a data collection pre-study on our own group members to test out our proceedure
  and identify any desired changes before reaching out to others for a larger data collection
  effort.

## Team Member Contributions

### Milo

1. Soldered battery conneciton pads on the Xiao, as well as pads on LRA and corresponding
   connection points on the DVR2605L breakout board.
2. Connected components on the breadboard with temporary power via the ESP32 to test the Xiao
   and the sensors.
3. Wired the battery, switch, and power delivery circuits.
    1. The Myoware is powered via a voltage regulator to keep a consistent ceiling for readings
       even as battery voltage decays with battery drain.
    2. A capacitor near the LRA powers large spikes from haptic pulses without dropping voltage
       for other components.
    3. The IMU is powered via the ESP32's 3v3 pin.
    4. The battery is charged via a charging circuit built into the Xiao.
4. Tested the full device on battery power, connecting to the app and trasmitting readings from
   both sensors over BLE.

### Bernardo

1. Researched on the specific models that we should use for our project
   (Huggingface or TinyML)
2. Built a small on-device machine learning model (6 → 16 → 8 → 1 neural network)
   that runs on the ESP32 after every rep and estimates reps in reserve (reps left
   before failure).
3. Added per-rep feature extraction on the ESP32: peak lift speed, moving time,
   range of motion, EMG RMS and EMG median frequency, each compared with the median
   of the set's first 3 reps.
4. Wrote a Python training script that trains the model, compares it with a
   velocity-only baseline using leave-one-subject-out testing, quantizes it to 8-bit
   weights (232 bytes) and exports it into the firmware.
5. Verified the model on the ESP32: a boot self-test matches the Python output,
   and each prediction takes about 20-30 µs.
6. Tested the full pipeline on real bicep curls: reps were counted, features
   measured and the model ran each rep. The model is currently trained on synthetic
   data, so its estimates aren't accurate yet.
7. Added a haptic alert when the model predicts 2 or fewer reps in reserve, and
   an “f” serial command that reports the model's error after a set taken to failure.
8. Added host tests that check the ESP32 feature and model code against Python,
   including tilted and flipped board mounts.
