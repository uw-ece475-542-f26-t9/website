## Weekly Progress

- Soldered Xiao battery pads, LRA pads, and DRV2605L breakout board
  connections.
- Built the full device on a breadboard and confirm that the device
  connects to the frontend and transmits IMU and EMG data while battery
  powered.
- Finalized and tested power delivery circuits to power the Myoware
  directly from the battery, important for keeping consistent readings

  integrated with its power circuit.

## Outcomes and Decisions

- We prioritized getting the full prototype working end to end, deciding to breadboard
  and test thoroughly rather than jump to a perfboard solder. Verified sensor acquisition,
  app display, and haptic feedback together on battery power before refining individual
  features.
- Keep model research and firmware integration moving in parallel. Use the available
  sensor data to explore features for fatigue estimation while continuing hardware tests.
- Use periodic vibration to test haptic feedback during integration. In the current
  setup, sensor readings reach the app, and the motor works on its own. Integration will
  follow from AI model results.

### Bernardo

- Researched on the specific models that we should use for our project
  (Huggingface or TinyML)
- Built a small on-device machine learning model (6 → 16 → 8 → 1 neural network)
  that runs on the ESP32 after every rep and estimates reps in reserve (reps left
  before failure).
- Added per-rep feature extraction on the ESP32: peak lift speed, moving time,
  range of motion, EMG RMS and EMG median frequency, each compared with the median
  of the set's first 3 reps.
- Wrote a Python training script that trains the model, compares it with a
  velocity-only baseline using leave-one-subject-out testing, quantizes it to 8-bit
  weights (232 bytes) and exports it into the firmware.
- Verified the model on the ESP32: a boot self-test matches the Python output,
  and each prediction takes about 20-30 µs.
- Tested the full pipeline on real bicep curls: reps were counted, features
  measured and the model ran each rep. The model is currently trained on synthetic
  data, so its estimates aren't accurate yet.
- Added a haptic alert when the model predicts 2 or fewer reps in reserve, and
  an “f” serial command that reports the model's error after a set taken to failure.
- Added host tests that check the ESP32 feature and model code against Python,
  including tilted and flipped board mounts.

### Adi

- Worked on the project's signal processing pipeline and explored Kalman filtering for fatigue estimation.
- The current pipeline band-pass filters the raw EMG signal (20–450 Hz), removes power-line interference, and extracts median frequency and RMS amplitude from 0.5 s windows.
- Analysis of the sensor-testing data showed that median-frequency estimates vary by approximately 10% between windows, while the underlying fatigue-related drift is only 0.02–0.12% per window.
- Proposed applying a Kalman filter to these extracted features rather than to the raw signal, whose frequency content must be preserved. The filter would produce a real-time estimate of the fatigue trend together with its uncertainty.
- The measured feature variance sets the filter's measurement noise. The process noise will be chosen from the required warning response time and validated on held-out recordings.
- The same framework provides a principled way to fuse EMG and wrist-IMU features into a single estimate of the reps remaining before form breakdown.
